# rgctl v0.4.27

rgctl can now round-trip source: opt-in lossless sidecars plus `rgctl writeback` verify, export, and patch a tree without reformatting it. Structured queries cover framework-migration census (import prefixes, annotation arguments, seedless edges, container blast radius). Release binaries cover Linux ARM64, musl, Intel macOS, and Windows ARM64, and `rgctl completions` prints a shell completion script.

```bash
rgctl --version   # 0.4.27

# Lossless index, then prove the bytes round-trip
rgctl discover . --lossless
rgctl writeback verify -f json

# Framework census without a rules catalog
rgctl -f json inventory --by import-prefix --prefix javax. --limit 20
rgctl -f json find --annotation Stateless,Singleton --show-attributes
rgctl -f json relations --edge injects

# Shell completions (no repo or .rgctl/ required)
rgctl completions zsh
```

## Highlights

### Lossless write-back (`discover --lossless`, `rgctl writeback`) (#185, #186)

Default `discover` is unchanged. `--lossless` (or `RGCTL_LOSSLESS=1`) writes two sidecars next to `.rgctl/graph.snapshot.bin`, reusing the worker's parse tree and BLAKE3 digest:

- **`.rgctl/content_store.bin` (RGCS v2)** — Zstd source frames, deduplicated by content hash, keeping original bytes (LF/CRLF, UTF-8 BOM, trailing whitespace).
- **`.rgctl/cst.archive.bin` (RGCT v1)** — Green CST: tree shape plus per-token widths, without a second copy of the source.

`find` and `inspect` JSON include `start_byte`, `end_byte`, `name_start_byte`, and `name_end_byte` on symbols. Design reference: [Lossless Write-Back Architecture](../design/lossless-writeback-architecture.md).

```bash
# 1. Index with lossless sidecars
rgctl discover . --lossless

# 2. Check BLAKE3 identity and CST leaf spans (add --strict to fail the process)
rgctl writeback verify -f json

# 3. Rebuild a tree from the content store alone
rgctl writeback export --output ./reconstructed -f json
rgctl writeback export --output ./reconstructed --file src/main -f json

# 4. Rename an identifier. CST token spans skip comments, strings, and longer names.
rgctl writeback patch --rename old_fn=new_fn --dry-run -f json
rgctl writeback patch --rename old_fn=new_fn --in-place -f json

# 5. Apply an explicit byte-span plan into another directory
rgctl writeback patch --plan mutations.json --output ./patched -f json
```

`mutations.json` is a list of non-overlapping ranges. `reason` is one of `rename`, `import_rewrite`, `call_site`, `plan`, or `other`. Edits in one file are applied from the end of the file backward, so earlier offsets stay valid. Each patched buffer is re-parsed; a new `ERROR` or `MISSING` node rejects that file unless you pass `--force`.

```json
{
  "files": [
    {
      "file": "src/App.java",
      "edits": [
        {
          "start_byte": 120,
          "end_byte": 128,
          "replacement": "newName",
          "reason": "rename"
        }
      ]
    }
  ]
}
```

`-f json` returns a trust ledger per file: `verified_identical`, `patched_verified`, `conflict_rejected`, or `syntax_error_rejected`, with before/after BLAKE3 hashes. `verify` also compares reconstructed bytes to the working tree when those files are still on disk.

### Structured migration queries (#186)

`inventory`, `find`, `relations`, `callers`, and `blast-radius` now answer framework-census questions directly.

```bash
# Import / namespace census. --prefix and --limit narrow the buckets.
rgctl -f json inventory --by import-prefix
rgctl -f json inventory --by import-prefix --prefix javax. --limit 20

# Annotation census. Comma-separated names; --show-attributes adds argument text.
rgctl -f json find --annotation Stateless,Singleton,Stateful,MessageDriven --show-attributes
rgctl -f json find --annotation Route,HttpGet,tokio::main --show-attributes

# Every edge of one type. Omit the symbol. Default direction is out.
rgctl -f json relations --edge injects
rgctl -f json relations --edge exposesroute --direction out
rgctl -f json relations --edge implements --limit 50

# Callers and blast radius of a class, interface, struct, enum, or module
rgctl -f json callers ShoppingCartService --depth 2
rgctl -f json blast-radius ShoppingCartService --depth 2 --summary

# Roadmap JSON (still opt-in; not part of --full)
rgctl discover . --export-migration-hints
# writes .rgctl/migration_plan.json
```

- **`--by import-prefix`** groups `Import` nodes by package or namespace. Separators follow the language (`.`, `::`, `/`, `\`). Binding suffixes such as `fastapi.routing:APIRouter` are stripped. Relative imports (`./`, `../`, `self`, `super`) are left out. The unfiltered scan reads the mmap snapshot directly.
- **`--annotation`** takes a comma-separated list and matches `@Ann`, `#[attr]`, `[Attr]`, and namespaced forms. A qualified name such as `javax.ws.rs.Path` or `tokio::main` must match that namespace. A simple name such as `Path` matches any namespace. **`--show-attributes`** attaches argument text from `.rgctl/annotation_args.json` when the plugin recorded it (Java, Kotlin, Scala, C#, Rust, Python, PHP, TypeScript, JavaScript). Marker annotations fall back to the simple name.
- **`relations` without a symbol** lists every edge of `--edge` (for example `injects`, `exposesroute`, `annotatedwith`, `implements`), bounded by `--limit`.
- **`callers` and `blast-radius` on a container** resolve the type even when a constructor shares its name, then roll up member functions and `Injects` edges. Qualified names may use `.`, `::`, or `\`.

### Shell completions (#149, #176)

`rgctl completions <bash|zsh|fish|elvish|powershell>` prints a completion script from the same CLI definition as `--help`. It does not open a repo or `.rgctl/`. Regenerate the script after upgrading. Setup: [Installation → Shell completions](../installation.md#shell-completions).

```bash
mkdir -p ~/.local/share/bash-completion/completions
rgctl completions bash > ~/.local/share/bash-completion/completions/rgctl

mkdir -p ~/.zfunc
rgctl completions zsh > ~/.zfunc/_rgctl
# ~/.zshrc: fpath=(~/.zfunc $fpath); autoload -Uz compinit && compinit

rgctl completions fish > ~/.config/fish/completions/rgctl.fish
```

```powershell
rgctl completions powershell | Out-String | Invoke-Expression
```

### Release binaries: ARM64, musl, Intel macOS, Windows ARM (#127, #182)

GitHub Release assets now include:

| Platform | Asset |
|----------|--------|
| Linux GNU x86_64 | `rgctl-*-x86_64-unknown-linux-gnu.tar.gz` |
| Linux GNU ARM64 | `rgctl-*-aarch64-unknown-linux-gnu.tar.gz` |
| Linux musl x86_64 | `rgctl-*-x86_64-unknown-linux-musl.tar.gz` |
| Linux musl ARM64 | `rgctl-*-aarch64-unknown-linux-musl.tar.gz` |
| macOS Apple Silicon | `rgctl-*-aarch64-apple-darwin.tar.gz` |
| macOS Intel | `rgctl-*-x86_64-apple-darwin.tar.gz` |
| Windows x86_64 | `rgctl-*-x86_64-pc-windows-msvc.zip` |
| Windows ARM64 | `rgctl-*-aarch64-pc-windows-msvc.zip` |

The install script picks GNU or musl from the host (Alpine and musl `ldd` select musl):

```bash
curl -fsSL https://rgctl.io/install.sh | sh
rgctl --version
```

GNU builds link a recent glibc. On older hosts where `./rgctl` reports `GLIBC_… not found`, use the matching musl archive. Musl builds omit the optional `semantic index --embedder code-daemon` mode; the default vocab embedder is included. Build from source when you need the ONNX embedder on musl.

### Documentation (#189, #190)

Architecture, design, and CLI docs were rewritten to match this tree: Kantra pages removed, write-back and structured queries documented in the [user guide](../user-guide.md) and [installation](../installation.md) docs, and the design set aligned with the current snapshot and analysis pipeline.

### Contributor preflight (#174, #175)

`./scripts/preflight-pr.sh` no longer rebuilds the workspace on every invocation. A warm `--lint` run is a few seconds; a warm `--full` run is on the order of a minute and a half. `target/` growth that exhausted CI runners (`No space left on device`) is bounded, and the split `ci*.yml` workflows share that compile.

## Breaking changes

| Changed | Migration |
|---------|-----------|
| Konveyor Kantra is removed: `rgctl rules`, `discover --with-kantra` / `--kantra-*`, `.rgctl/kantra_findings.json`, `.rgctl/dashboard/kantra_index.json`, `NodeType::KantraRule` / `KantraRuleset`, `EdgeType::Violates`, and the dashboard Static rules room ([#177](https://github.com/rgctl/rgctl/issues/177)) | Use `inventory --by import-prefix`, `find --annotation … --show-attributes`, `relations`, `discover --export-migration-hints`, and `writeback` |
| `discover --full` runs CFG, Universe, harmonic centrality, taint, and the semantic index | Pass `--with-security`, `--with-git`, `--scip`, or `--export-migration-hints` beside `--full` when you want those stages. Re-discover to drop stale Kantra artifacts |
